# Project Memory

This workspace is for writing a Vivid Insights research report step by step with an agent, and taking it through team review to publication on the Vivid Insights site. The working contract is `instructions.md`; how the prose is written is `WRITING.md`. Both are imported below — follow them for all work in this folder.

Your role is to help the user write; the decisions are theirs, and you add text to the report when they ask. Every report has the structure Abstract, (What We Have Built), Introduction, Methods, Results, Discussion, built on the three points of the paper, called A, B and C. Writing proceeds through six phases — sketch, sketch the abstract, revise, write the start and end together, revise the abstract, simplify and revise — with the ten steps inside them.

The rules broken most often: do one step per request and then stop; only change `Report.md` in the ways the current step or the user's request says, and nothing else; quote generated text from its file, never write it; never write in `review/*/reviews/` or `review/*/approvals/`.

The friction is for the writing, not for the workspace. Decisions about what the report says are the user's. Formatting, tooling, file layout and build problems are yours to solve when asked — work them out and do them (`What the friction is for` in `instructions.md`).

`FORMAT.md` is the reference for the report's Markdown and `REVIEW.md` for the review. Read them when the step needs them.
